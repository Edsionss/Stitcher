# 核心模块设计详解

## 1. 拖拽系统设计 (Drag System)

### 1.1 架构设计
新的拖拽系统将完全基于 `interact.js` 构建，以统一处理所有拖拽、缩放、放置等交互，取代原有的原生API和手动事件监听。

#### 核心交互流程
1.  **从组件面板拖拽**:
    -   `interact(ComponentItem).draggable()` 启动拖拽。
    -   `listeners.onstart`: 记录组件元数据，并创建一个临时的预览元素（Drag Proxy）跟随鼠标。
    -   `listeners.onmove`: 更新预览元素的位置。
2.  **在画布上放置**:
    -   `interact(Canvas).dropzone()` 将画布设为放置区域。
    -   `listeners.ondrop`: 接收 `ComponentItem` 的拖拽事件，读取组件元数据，并在鼠标位置创建一个新的 `CanvasComponent` 实例（通过更新Pinia Store）。
3.  **在画布上操作**:
    -   `interact(CanvasComponent).draggable()` 实现组件在画布内的自由移动。
    -   `interact(CanvasComponent).resizable()` 实现组件的缩放。
    -   `listeners.onmove` / `listeners.onresize`: 将移动和缩放的增量（dx, dy）或尺寸更新到Pinia Store中对应组件的 `style` 对象上。

#### 接口与状态
- **状态管理**: 所有组件的位置 (`x`, `y`) 和尺寸 (`width`, `height`) 状态都由 `componentTreeStore` (Pinia) 统一管理。`interact.js` 的回调函数只负责触发Store的Action来更新状态，实现单向数据流。
- **配置**: `interact.js` 的配置（如吸附、约束等）将在一个专门的 `useInteraction` 组合式函数中进行管理。

### 1.2 实现细节

#### 1.2.1 拖拽与放置 (Drag and Drop)
```typescript
// 在 useInteraction.ts 或类似的组合式函数中

import interact from 'interactjs';
import { useComponentTreeStore } from '@/stores/componentTree';

// 初始化从组件面板的拖拽
export function initDraggableComponents(selector: string) {
  interact(selector).draggable({
    listeners: {
      start(event) {
        // 1. 获取组件元数据
        const componentMeta = getComponentMetaFromElement(event.target);
        // 2. 将元数据附加到交互事件上，以便dropzone可以访问
        event.interaction.meta = { componentMeta };
      },
      move(event) {
        // interact.js 默认会处理预览元素的移动
      }
    }
  });
}

// 初始化画布的放置区域
export function initCanvasDropzone(selector: string) {
  interact(selector).dropzone({
    ondrop(event) {
      const componentMeta = event.relatedTarget.interaction.meta.componentMeta;
      if (!componentMeta) return;

      // 计算在画布上的精确坐标 (考虑缩放和滚动)
      const { x, y } = calculateDropPosition(event);
      
      const componentTree = useComponentTreeStore();
      componentTree.addComponent({
        type: componentMeta.type,
        library: componentMeta.library,
        styles: {
          position: 'absolute',
          left: `${x}px`,
          top: `${y}px`,
          width: '100px', // 默认尺寸
          height: '50px',
        },
        // ... 其他属性
      });
    }
  });
}
```

#### 1.2.2 画布内移动与缩放 (Draggable & Resizable in Canvas)
```typescript
// 在 CanvasComponent.vue 中
import interact from 'interactjs';
import { useComponentTreeStore } from '@/stores/componentTree';

onMounted(() => {
  const componentId = props.component.id;
  const componentTree = useComponentTreeStore();

  interact(elementRef.value)
    .draggable({
      listeners: {
        move(event) {
          const { dx, dy } = event;
          // 更新Store中的组件位置
          componentTree.moveComponent(componentId, dx, dy);
        }
      },
      modifiers: [
        // 使用修饰符实现网格吸附
        interact.modifiers.snap({
          targets: [interact.snappers.grid({ x: 10, y: 10 })],
          range: Infinity,
          relativePoints: [{ x: 0, y: 0 }]
        })
      ]
    })
    .resizable({
      edges: { left: true, right: true, bottom: true, top: true },
      listeners: {
        move(event) {
          const { width, height } = event.rect;
          const { left, top } = event.deltaRect;
          // 更新Store中的组件尺寸和位置
          componentTree.resizeComponent(componentId, { width, height, dx: left, dy: top });
        }
      },
      modifiers: [
        // 同样可以添加吸附修饰符
        interact.modifiers.snapSize({
          targets: [interact.snappers.grid({ width: 10, height: 10 })],
        })
      ]
    });
});
```

#### 1.2.3 吸附与辅助线 (Snapping & Guidelines)
- **网格吸附**: 直接使用 `interact.modifiers.snap` 和 `interact.snappers.grid` 即可实现，如上例所示。
- **智能辅助线**:
  1.  在组件开始拖拽 (`draggable.onstart`) 时，计算并缓存画布上所有其他静态组件的边缘坐标（上、中、下、左、中、右）。
  2.  在拖拽过程 (`draggable.onmove`) 中，将当前拖拽组件的边缘与缓存的坐标进行比较。
  3.  如果差值在某个阈值（如 `5px`）内，则触发吸附。可以通过动态创建一个 `snap` 修饰符或直接修改 `event.dx/dy` 来实现。
  4.  同时，在UI上渲染出对应的红色辅助线。
  5.  拖拽结束时 (`draggable.onend`) 清除所有辅助线。

### 1.3 性能优化
- **事件监听**: `interact.js` 内部已对 `pointer/touch/mouse` 事件做了优化。我们只需确保在 `move` 事件的回调中，更新Store的操作是轻量级的。
- **DOM操作**: 避免在 `move` 事件中直接操作DOM。所有UI更新都应由Vue的响应式系统在Store状态变更后触发，这是最高效的方式。
- **缓存**: 对于智能辅助线，对静态组件的边缘坐标进行缓存，仅在画布组件布局发生变化时才重新计算，避免在拖拽的每一帧都进行大量计算。
