## 1. Vue组件开发规范

### 1.1 组件命名规范

#### 文件命名

**规则**:
- 使用PascalCase命名法
- 以.vue结尾
- 组件名应该是名词或形容词
- 保持简洁和语义化

**正确示例**:
```typescript
UserProfile.vue
ButtonGroup.vue
DataTable.vue
PropertyPanel.vue
```

**错误示例**:
```typescript
user-profile.vue     // kebab-case
button.vue           // 太简单，无意义
someComponent.vue    // 太抽象
```

#### 组件导出

**使用**:
```vue
<script setup lang="ts">
// ... 逻辑
</script>
```

**避免**:
```vue
<script lang="ts">
export default {
  // ... 旧的Options API
}
</script>
```

### 1.2 Props规范

#### 命名规则
- 使用camelCase命名法
- 类型和默认值必须声明
- 使用 `defineProps` 宏（Vue 3.3+）

**正确示例**:
```typescript
import type { ComponentProps } from '@/types'

const props = defineProps<{
  title: string
  size?: 'small' | 'medium' | 'large'
  disabled?: boolean
  items: ComponentProps[]
}>()

const { title, size = 'medium', disabled = false } = props
```

#### Props验证
- 基本类型使用TypeScript类型注解
- 复杂验证使用 `withDefaults` 配合 `defineProps`

```typescript
const props = withDefaults(defineProps<{
  variant?: 'primary' | 'secondary'
  loading?: boolean
}>(), {
  variant: 'primary',
  loading: false
})
```

### 1.3 Emits规范

#### 声明方式
```typescript
const emit = defineEmits<{
  (e: 'change', value: string): void
  (e: 'update:visible', visible: boolean): void
  (e: 'click', event: MouseEvent): void
}>()

// 使用
emit('change', newValue)
emit('update:visible', false)
```

#### 事件命名
- 使用kebab-case
- 使用DOM原生事件名称或自定义动词
- 保持语义化

**正确示例**:
```typescript
emit('click')
emit('change')
emit('update:visible')
emit('item-selected')
```

### 1.4 组合式函数规范

#### 命名规则
- 使用camelCase命名法
- 使用`use`前缀
- 文件名以`.ts`结尾

**正确示例**:
```typescript
// useUser.ts
export function useUser() {
  // ... 逻辑
  return {
    user,
    login,
    logout
  }
}
```

#### 使用场景
- 组件复用逻辑
- 状态管理
- 业务逻辑封装

## 2. TypeScript类型规范

### 2.1 基础类型

#### 接口 vs 类型别名

**接口（Interface）**:
- 适用于对象结构
- 支持合并（declaration merging）
- 适合公开API

```typescript
export interface User {
  id: string
  name: string
  email: string
}
```

**类型别名（Type Alias）**:
- 适用于联合类型、基础类型
- 适合内部实现

```typescript
export type Status = 'loading' | 'success' | 'error'
export type ID = string | number
```

### 2.2 泛型规范

#### 命名约定
- 使用有意义的字母
- T, U, K, V用于简单泛型
- 有意义的名字用于复杂场景

**正确示例**:
```typescript
function createArray<T>(length: T): T[] {
  return new Array(length)
}

function mapObject<K extends string, V, R>(
  obj: Record<K, V>,
  fn: (value: V, key: K) => R
): Record<K, R> {
  // ... 实现
}
```

### 2.3 工具类型

#### 常用工具类型
- `Partial<T>` - 全部属性可选
- `Required<T>` - 全部属性必需
- `Pick<T, K>` - 选择部分属性
- `Record<K, T>` - 键值对对象

```typescript
export interface ComponentProps {
  id: string
  title: string
  visible: boolean
}

// 部分属性可选
export type OptionalProps = Partial<ComponentProps>

// 只选择部分属性
export type VisibleProps = Pick<ComponentProps, 'id' | 'visible'>
```

### 2.4 类型导入

#### 导入规则
- 使用 `import type` 导入纯类型
- 使用 `import` 导入值和类型混合

**正确示例**:
```typescript
import type { ComponentMeta, EventHandler } from '@/types'
import { eventBus } from '@/utils/eventBus'
```

## 3. Git提交规范

### 3.1 提交信息格式

**格式**:
```
<type>(<scope>): <subject>

<body>

<footer>
```

**类型（type）**:
- `feat` - 新功能
- `fix` - 修复bug
- `docs` - 文档更新
- `style` - 代码格式化
- `refactor` - 重构
- `test` - 测试相关
- `chore` - 构建/工具相关

**范围（scope）**:
- `editor` - 编辑器相关
- `component` - 组件相关
- `store` - 状态管理
- `ui` - UI相关

**正确示例**:
```
feat(editor): 实现画布缩放功能
```

```
fix(component): 修复Button组件disabled状态不生效问题
```

```
docs(README): 更新安装说明
```

### 3.2 提交钩子配置

#### commit-msg钩子
使用Husky配置提交信息验证：

```bash
# .husky/commit-msg
#!/usr/bin/env sh
. "$(dirname -- "$0")/_/husky.sh"

npx --no-install commitlint --edit "$1"
```

#### commitlint配置
```typescript
// commitlint.config.js
module.exports = {
  extends: ['@commitlint/config-conventional'],
  rules: {
    'type-enum': [
      2,
      'always',
      ['feat', 'fix', 'docs', 'style', 'refactor', 'test', 'chore']
    ],
    'subject-case': [0, 'always']
  }
}
```

## 4. 代码审查流程

### 4.1 审查清单

#### 功能性
- [ ] 代码实现符合需求
- [ ] 边界情况处理正确
- [ ] 无明显性能问题
- [ ] 错误处理完善

#### 代码质量
- [ ] 遵循项目规范
- [ ] 变量/函数命名清晰
- [ ] 代码注释充分
- [ ] 无重复代码

#### 安全性
- [ ] 无XSS风险
- [ ] 无SQL注入风险
- [ ] 权限控制正确
- [ ] 敏感信息不暴露

#### 测试
- [ ] 单元测试覆盖
- [ ] 集成测试通过
- [ ] E2E测试通过
- [ ] 测试用例合理

### 4.2 PR流程

1. **创建分支**
   ```bash
   git checkout -b feature/xxx
   ```

2. **开发与提交**
   - 遵循提交规范
   - 及时提交代码

3. **创建PR**
   - 填写PR模板
   - 提供充分说明
   - 关联Issue

4. **代码审查**
   - 至少2人Review
   - 解决所有Comment

5. **合并与删除分支**
   - 使用Squash合并
   - 删除远程分支

## 5. 测试规范

### 5.1 单元测试

#### 使用Vitest
```typescript
// Button.test.ts
import { describe, it, expect } from 'vitest'
import { mount } from '@vue/test-utils'
import Button from './Button.vue'

describe('Button', () => {
  it('renders correctly', () => {
    const wrapper = mount(Button, {
      props: { text: 'Click me' }
    })
    expect(wrapper.text()).toBe('Click me')
  })

  it('emits click event', async () => {
    const wrapper = mount(Button)
    await wrapper.trigger('click')
    expect(wrapper.emitted('click')).toHaveLength(1)
  })
})
```

#### 测试覆盖要求
- 核心业务逻辑：> 80%
- 组件：> 70%
- 工具函数：> 90%

### 5.2 E2E测试

#### 使用Playwright
```typescript
// editor.spec.ts
import { test, expect } from '@playwright/test'

test('editor workflow', async ({ page }) => {
  await page.goto('/editor')

  // 添加组件
  await page.click('[data-testid="component-button"]')
  await page.dragAndDrop('[data-testid="component-item"]', '[data-testid="canvas"]')

  // 验证
  expect(await page.locator('[data-testid="canvas"] .button')).toBeVisible()
})
```

## 6. 项目结构规范

### 6.1 目录结构

```
src/
├── components/          # 组件
│   ├── editor/         # 编辑器组件
│   └── common/         # 通用组件
├── composables/        # 组合式函数

├── types/              # TypeScript类型
├── utils/              # 工具函数
├── assets/             # 静态资源
├── styles/             # 样式文件
└── adapters/           # 适配器
```

### 6.2 文件命名规范

| 类型 | 规范 | 示例 |

## 📌 最佳实践

### 1. 性能优化
- 合理使用`computed`而非`watch`
- 避免在`computed`中做复杂计算
- 大量数据使用虚拟滚动
- 图片懒加载

### 2. 错误处理
- 使用Try-Catch包装异步操作
- 提供用户友好的错误信息
- 记录错误日志
- 优雅降级

### 3. 代码复用
- 提取公共逻辑到composable
- 封装通用组件
- 使用TypeScript类型定义
- 避免硬编码

### 4. 可维护性
- 单一职责原则
- 清晰的代码注释
- 统一的代码风格
- 合理的项目结构
